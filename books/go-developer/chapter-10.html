Chapter 10: Parameters, Return Values and Multiple Returns

Section 1: What a Parameter Is

What a Parameter Is is the focus of this section, and it belongs to the wider topic of parameters and return values in Go. Go makes this contract explicit in the function signature, which lists every parameter with its type and every return value with its type. Multiple return values extend the same idea, letting a function hand back a result together with an error, which is Go's standard way of reporting that something went wrong.

A return value is declared after the parameter list, as a type, and the function must return a value of that type on every path that reaches the end. The return statement gives the value back and ends the function immediately, so code after a return in the same block never runs. A caller can store the returned value in a variable, use it directly in an expression, or ignore it, although ignoring a value that reports an error is usually a mistake. Functions that answer a yes-or-no question return a boolean, functions that compute something return a number or a string, and functions that might fail return a result plus an error.

When you work with what a Parameter Is, keep the example in this section beside you and read it slowly, line by line, asking what each part contributes to what a Parameter Is. To study parameters and returns, call a function with several different arguments and predict the result each time before running it. Try the normal case, an edge case such as zero or an empty string, and a case that should fail, and check that the error return behaves as you expect. That strictness is the signature protecting you from silently losing a result or an error.

Another pitfall is designing a signature with so many parameters that callers constantly get them confused, or with parameters that are almost never used, which suggests the function is doing more than one job. Go has no default parameter values, so optional behaviour must be expressed another way, such as a separate function, a configuration struct, or a variadic list. Also watch for a function that returns a boolean and an error where the boolean is meaningless when the error is set: callers must learn to check the error first, before reading the result, or they will act on a value that means nothing.

In short, a function signature is a promise: these are the inputs, in this order and of these types, and these are the outputs you will get back. Keep signatures short and honest, pass arguments in order, return a result together with an error when failure is possible, and always check that error before using the result. import "fmt"

func main() {
	total, err := divide(10, 2)
	if err != nil {

	} else {

	}
