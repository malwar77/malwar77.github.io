Section 1: What a Struct Is

In this section you will work through what a struct is, one of the building blocks of structs in Rust, and you will learn to recognise it in real code, explain it in plain words, and use it deliberately rather than by copying an example you do not yet understand. The idea behind what a struct is is practical: it answers a question that comes up again and again when you write Rust programs, namely how to keep data safe, clear, and under control while your program grows from a few lines into something larger and harder to hold in your head. Think of what a struct is as one tool in a growing Rust toolkit, modest on its own, but powerful when combined with the tools you already know, because it lets you express ideas that were awkward or impossible before. Structs are defined with the struct keyword, and the definition is usually placed near the top of a file so readers can see the shape of the data early.

Accessing a field uses dot notation, which reads naturally and keeps related data together when you pass a struct into a function or store it in a vector. A struct can own its data, for example by holding Strings, or it can borrow data, although owned fields are simpler for beginners and are the usual starting point. Making a struct mutable lets you change its fields, but mutability applies to the whole struct value, not to individual fields in isolation. Field init shorthand lets you write a field name once when a variable of the same name already holds the value, which keeps struct creation concise and clear.

Struct update syntax lets you build a new struct from an existing one, changing only the fields you list and copying or moving the rest from the original. A tuple struct has fields without names, identified only by position, and it is useful when the type itself carries the meaning, such as a colour or a point. A unit struct has no fields at all, and it is useful as a marker type, for example to distinguish one kind of operation from another in the type system. Structs can hold other structs as fields, which lets you build larger shapes from smaller ones, such as an address inside a person or a chapter inside a book.

Functions that take a struct as a parameter can work with the whole grouped value, instead of receiving a long list of separate arguments in the right order. Deriving Debug for a struct lets you print it with a debug format, which is invaluable when you are checking what a program actually stored. Choosing good field names is part of designing a struct, because names that describe the data clearly reduce confusion far more than comments alone.
