Section 1: What a Method Is

In this section you will work through what a method is, one of the building blocks of methods and associated functions in Rust, and you will learn to recognise it in real code, explain it in plain words, and use it deliberately rather than by copying an example you do not yet understand. The idea behind what a method is is practical: it answers a question that comes up again and again when you write Rust programs, namely how to keep data safe, clear, and under control while your program grows from a few lines into something larger and harder to hold in your head. Think of what a method is as one tool in a growing Rust toolkit, modest on its own, but powerful when combined with the tools you already know, because it lets you express ideas that were awkward or impossible before. A method that takes self by value consumes the value, a method that takes a reference borrows it, and a method that takes a mutable reference may change it.

Most methods borrow their receiver, because reading or updating a value in place is more common than consuming it, and borrowing keeps the value usable afterwards. An implementation block groups all the methods and associated functions for one type, and a type may have several implementation blocks in the same module. Methods make code read like a description of behaviour, because a call such as task.mark_done reads as an action performed by that task itself. Associated functions are useful for constructors, for building a value from parts, and for operations that do not belong to any single existing value.

The Self type inside an implementation block refers to the type being implemented, which keeps signatures readable when the type name is long. Method syntax is a convenience built on ordinary functions, because a method call is equivalent to calling the function with the receiver as its first argument. Choosing a method over a free function is often a readability decision: if an operation is naturally about one type, making it a method signals that clearly. A method can return a value, a reference, or nothing, and its return type should match what a caller would expect from the action it performs.

Mutable methods require a mutable receiver, so a caller must declare the value mutable before calling a method that changes it. Methods can call other methods on the same value, which lets you build small, focused methods and combine them into larger behaviour without duplication. Associated functions that act as constructors often take the field values as parameters and return Self, giving callers a single, documented way to create a value. When a method and a field share a name, the method call still works, because Rust distinguishes a method call with parentheses from a field access without them.
