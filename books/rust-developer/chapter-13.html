Section 1: What a Slice Is

In this section you will work through what a slice is, one of the building blocks of slices in Rust, and you will learn to recognise it in real code, explain it in plain words, and use it deliberately rather than by copying an example you do not yet understand. The idea behind what a slice is is practical: it answers a question that comes up again and again when you write Rust programs, namely how to keep data safe, clear, and under control while your program grows from a few lines into something larger and harder to hold in your head. Think of what a slice is as one tool in a growing Rust toolkit, modest on its own, but powerful when combined with the tools you already know, because it lets you express ideas that were awkward or impossible before. Slices let functions accept a part of a string or a vector, which makes those functions useful for many inputs, not just for one exact type or size.

Because a slice borrows its data, the original value must stay alive while the slice is used, and the compiler enforces that requirement for you. Indexing a string by byte position can fail on text that is not plain ASCII, because Rust strings are UTF-8 and a character may occupy more than one byte. The safest way to work with string slices is to split on clear boundaries, such as spaces, or to use methods that respect character boundaries. A function that takes a string slice can accept both a String and a string literal, which is why slice parameters are preferred in most Rust code.

Vector slices work the same way as string slices, giving a borrowed view of some or all of the elements in a vector, in their original order. Slices have a length and a starting point, but they do not copy the elements, so creating a slice is cheap even when the underlying data is large. When you slice a vector, the result borrows the vector, so you cannot change the vector in a way that would invalidate the slice while the slice is alive. Returning a slice from a function is safe only when the data it points to outlives the function call, and the compiler will reject a slice into a temporary value.

A slice pattern appears everywhere in Rust programs, from finding the first word in a sentence to processing a window of numbers in a list. Comparing slices is straightforward, because two slices with the same contents compare equal even when they come from different original values. Slices encourage you to think in terms of ranges and windows, rather than copying whole collections every time you need a smaller part of them.
