The goal here is not to memorise a trick, but to build a clear mental picture you can reuse whenever a similar problem appears in your own work.

In practice, why functions exist works by giving PHP a clear rule to follow and a set of values to test against that rule. You supply the data, PHP checks it in order, and the program then follows the path that matches what it finds. That order matters, because the first matching path is usually the one that runs, and later paths are skipped once a match is found. Think of it as a set of labelled doors: PHP opens the door whose label fits the current value, and it does not need to open every other door. Keeping that picture in mind helps you predict behaviour before you run the code.

A helpful way to learn why functions exist is to start with a tiny, concrete situation you already understand, such as a score, a name, a price, or a simple yes-or-no choice. Write down two or three possible values, decide what should happen for each one, and only then turn those decisions into code. If you can explain the expected result for each value in plain language, the code itself becomes much easier to write and to check.
