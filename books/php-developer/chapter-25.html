There is a difference between code that happens to work once and code that works reliably. With what validation means, reliable code means thinking about what could go wrong as well as what should go right. Ask yourself what happens with an empty value, a missing value, or a value of the wrong kind. A program that handles those cases calmly is much more useful than one that only works when everything is perfect. Build that habit now, while your programs are still small.
