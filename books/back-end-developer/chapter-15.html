db.execute("PRAGMA foreign_keys = ON")
db.execute("CREATE TABLE IF NOT EXISTS customers (id INTEGER PRIMARY KEY, name TEXT)")
db.execute("CREATE TABLE IF NOT EXISTS orders (id INTEGER PRIMARY KEY, customer_id INTEGER, FOREIGN KEY(customer_id) REFERENCES customers(id) ON DELETE CASCADE)")
db.commit()
rows = db.execute("SELECT customers.name, orders.id FROM customers JOIN orders ON orders.customer_id = customers.id").fetchall()
print(rows)
db.close()

Beginners usually stumble on Relationships and the Rest of Your API in a few familiar ways. One is skipping the small example and jumping straight to a large project, which hides mistakes until they are expensive to fix. Another is changing several things at once, so no one can tell which change caused a new result. A third is trusting a first result without checking edge cases, such as empty data, unusual spellings, or a missing row. The cure for all three is the same patient habit: run the code, read the output, change one thing, and run it again.

Before you move on, summarise Relationships and the Rest of Your API in two or three sentences without looking back. Then try the small variation suggested by the example: change one value or one name, predict the new output, and run the code to check. That short loop, predict, run, compare, is how back-end developers build reliable intuition, and it works just as well for databases as it does for any other part of a server.
