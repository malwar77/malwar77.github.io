Chapter 28: Variables: Custom Properties

Section 1: What a CSS Variable Really Is

Start with the idea behind What a CSS Variable Really Is, not with its syntax. In CSS, every feature exists because a real page needed it: a designer wanted an element to move, change, resize, or respond to a different screen, and a property was added to make that change possible without JavaScript. What a CSS Variable Really Is fits that story. It gives you a controlled way to make one part of a page behave differently, and it works together with the rest of your stylesheet rather than replacing it. If you understand the problem it solves, the syntax that follows will feel like a label for an idea you already own, not a code to memorise blindly.

How What a CSS Variable Really Is behaves depends on the context around it. The same declaration can look different on a block element and an inline element, on a large screen and a small one, or inside a flex container versus a grid container. That is not a flaw in CSS; it is how a language designed for many kinds of pages has to work. Your job is to notice the context: what is the element's display type, what is its parent doing, and is another rule with higher specificity competing with yours? When you check those three questions first, most mysterious results become ordinary, and you stop changing values at random in the hope that something will work.

A useful way to learn What a CSS Variable Really Is is to build the smallest possible example that shows it working. Give yourself one element, one rule, and one clear change to observe. If the change does not appear, check the basics before you doubt the feature: is the stylesheet linked, is the selector spelled correctly, is the property name right, and is another rule overriding yours? Most beginners' problems are spelling, linking, or specificity problems, not problems with the feature itself. A tiny example makes those problems visible, while a large page hides them under dozens of other rules.

Another common mistake is forgetting the people who will use the page. Some users navigate with a keyboard, some use screen readers, some are sensitive to motion, and some view your page on a slow connection or a small, dim screen. What a CSS Variable Really Is should never make a page harder to use for those visitors. That means keeping text readable, keeping interactive elements reachable and visible, and providing a calmer alternative when motion or colour could cause harm or confusion. Thinking about those users early is not extra work; it is the same work, done properly, and it usually produces a cleaner design for everyone.

A good rule of thumb for What a CSS Variable Really Is is to start simple, keep it consistent, and only add complexity when a real need appears. Use the same values across similar elements so the page feels like one design instead of a collection of experiments. Write a short comment in your stylesheet when a rule is doing something subtle, so future you — or a teammate — understands why it is there.

/* What a CSS Variable Really Is */
.button {
  background: var(--btn-bg, #2563eb);
  color: var(--btn-text, #ffffff);
}
.button--alt {
  --btn-bg: #0f766e;
}

Section 2: Declaring a Variable with Two Dashes

Before you write anything, ask what Declaring a Variable with Two Dashes is for and what it is not for. A CSS feature that is used for the wrong job will fight you: it will need extra rules to undo its side effects, it will break in a surprising place, or it will make your stylesheet harder to read. Declaring a Variable with Two Dashes has a clear, narrow purpose, and this section keeps that purpose in focus. You will learn where it belongs in a normal stylesheet, what kind of element it works best on, and what to reach for instead when a different tool fits better. That judgement is what separates a developer who copies snippets from one who builds layouts with confidence.

The syntax for Declaring a Variable with Two Dashes follows the same pattern as the rest of CSS, which is good news if you already know the basics. A property name, a colon, a value, and a semicolon are all there is to a single declaration, and most of the learning is in choosing good values and combining declarations sensibly. You will see short examples in this section, and you should read each one slowly: name the selector, name each property, and say in your own words what each value does. That habit turns examples from things you copy into things you understand, and understanding is what lets you adapt an example to your own page instead of forcing your page to match the example.

When you read the code example, pay attention to the values, not just the property names. Values are where the real decisions live: how far, how fast, how large, which colour, which direction. A good value is chosen for a reason, and that reason usually comes from the design: the spacing system, the colour palette, the type scale, or the way a user will interact with the element. Try swapping a value for something clearly wrong, like a huge number, and watch what breaks. Exaggerated values are excellent teachers because they make an invisible effect impossible to miss.

Debugging Declaring a Variable with Two Dashes is mostly a matter of narrowing down the cause. If the result is wrong, isolate the element in a small test page, remove unrelated rules, and add them back one at a time until the problem returns. Use your browser's developer tools to see which rules actually apply to the element and which ones are crossed out by the cascade. That panel is not just for experts; it is the fastest way to answer the question every CSS developer asks, which is why is this element not doing what I wrote? Learning to read that panel early will change how quickly you solve layout problems for the rest of your career.

By the end of this section you should be able to explain Declaring a Variable with Two Dashes in plain words, write a short example from memory, and predict what will happen when you change its main value. You do not need to memorise every possible value today; you need the core idea, one working example, and the confidence to look up the rest when you need it. Professional developers look things up constantly.

/* Declaring a Variable with Two Dashes */
.card {
  --card-gap: 0.75rem;
  gap: var(--card-gap);
  border-radius: var(--radius, 0.5rem);
}

Section 3: Reading a Variable with var()

This section is about Reading a Variable with var(). It is a good place to slow down and build a clear mental picture before you type any code, because most confusion in CSS comes not from a single property but from a fuzzy idea of what that property is supposed to do. Think of Reading a Variable with var() as one tool with one job: it changes how an element looks or behaves in a specific, predictable way, and it leaves everything else alone unless you tell it otherwise. When you can say that job in one plain sentence, you can read other people's stylesheets faster, spot your own mistakes sooner, and choose the right property instead of guessing. That plain sentence is worth more than memorising a long list of values.

In practice, Reading a Variable with var() works through a small set of properties and values that you combine. You write a selector, you add the property, and you give it a value that the browser can interpret. The browser then applies that value when it paints the element, and it reapplies it whenever the element's state changes, the viewport changes, or another rule overrides it. Nothing happens by magic, and nothing is stored between page loads unless you write it into the stylesheet again. That predictability is a strength: if you can read the rule, you can predict the result, and if the result surprises you, you can trace it back to a specific rule.

Look closely at the example in this section and trace it step by step. Start with the element the selector targets, then follow each declaration in order and imagine the browser applying it. Ask yourself what the page would look like if you removed one declaration: that missing piece tells you what that declaration is really doing. Then change one value at a time in your own editor and reload the page. Changing one thing at a time is slower than changing five, but it teaches you five times as much, because you always know which change caused the difference you see. That discipline will save you hours on larger projects.

The most common mistake with Reading a Variable with var() is using it everywhere at once. It is tempting, once you learn a new effect, to apply it to every element on the page, but restraint is part of good design. One well-chosen effect guides the eye; twenty competing effects distract it. Ask whether this element needs the effect to be understood or used, or whether it is decoration that adds noise. If you cannot answer that question, leave the effect off and see whether the page still works. A page that works without decoration is a strong page, and decoration added afterwards will strengthen it rather than rescue it.

To practise Reading a Variable with var(), pick a small, real piece of a page you care about and apply it there, rather than in an abstract exercise. A button, a card, a heading, or a navigation link is enough. Write the rule, check it on a phone-sized window and on a desktop window, tab through it with your keyboard, and ask a friend to use it without instructions.

/* Reading a Variable with var() */
:root {
  --brand: #2563eb;
  --gap: 1rem;
}
.card {
  color: var(--brand);
  padding: var(--gap);
}
