    print(name, "->", line)

Code for ready to build the application stays readable when each function does one job and says so in its name. A function that reads notes should only read notes; a function that picks summary sentences should only pick sentences; a function that prints results should only print them. This separation means you can test each piece alone, replace one piece without breaking the others, and explain the program to someone else by walking through its parts in order. The example below shows that style in miniature, using only the Python standard library and files on your own machine.

When you think about ready to build the application, start with the person who will use the tool rather than with the cleverest method you know. A real tool earns its place by solving one small problem reliably, day after day, without demanding attention or creating new work. In AIDay that means the feature must work on the reader's own notes, on their own machine, with plain files they can open and read. If a feature needs a network connection, a secret key, or someone else's computer, it does not belong in this project. Keeping that test in mind makes every later choice simpler, because you can reject ideas quickly and spend your energy on the parts that genuinely help.
