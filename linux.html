Linux, explained properly

Linux is a kernel, not an operating system

The single fact that makes everything else about Linux make sense: what the kernel is, what a distribution adds on top of it, and why you never actually 'install Linux' — you install a distro.

How distros actually differ

Strip away the logos and most distros share the same kernel, commands and apps. The real differences are five: package manager, release model, desktop, defaults and community — and only some of them matter day to day.

Rolling vs fixed releases: how your system ages

The deepest split between distros is not the desktop or the logo — it is whether your system stands still and gets patched, or flows forward forever. Honest pros, cons, and the sensible middle grounds.

Linux guides

What Linux is actually used for

Not a hobbyist toy: Linux runs most of the web, every Android phone, and the toolkit of every security professional. Concretely, job by job.

"Should I learn Linux?" is easier to answer when you stop asking what Linux is and ask what it does all day. The list is not abstract. Linux quietly holds up most of the computing you already use — you have just never been introduced.

Servers and the cloud

The largest job by far. The overwhelming majority of web servers, cloud instances and containers run Linux, because it is free, scriptable, stable for years at a time, and happy with no screen attached at all. If you deploy a website or an API, you are deploying it onto Linux — knowing the system your code lives on stops being optional the first time something breaks at 2 a.m.

Phones, routers, and everything embedded

Android is built on the Linux kernel, so the most common computer on Earth already runs it. So do most home routers, smart TVs, NAS boxes, industrial controllers and a good share of cars and spacecraft. Linux scales down as gracefully as it scales up.

Security and penetration testing

The security industry's tools — scanners, proxies, password auditors, network analysers — are written for Linux first, because the system's openness lets them inspect everything. Entire distributions (Kali is the famous one, see the distro cards below) exist just to bundle those tools. If your goal is cybersecurity work, Linux is not a preference; it is the workplace.

Development

Developers live where their software runs. Since production is Linux, development environments match it: containers package Linux, CI pipelines run Linux, and the terminal skills transfer unchanged from a laptop VM to a cloud server on another continent.

Privacy and old hardware

No forced account, no advertising ID, no telemetry you did not agree to — and a lightweight distro can make a ten-year-old laptop genuinely useful again instead of e-waste. For a lot of people worldwide, that last one is not a philosophy. It is the computer they can afford to keep.

Learn Linux and you are not learning an operating system. You are learning how computers actually work underneath the glass — and that knowledge transfers to every machine you will ever touch.

Install ANY Linux distro in VirtualBox

One universal flow works for Ubuntu, Debian, Kali, Fedora and nearly everything else: ISO in, virtual machine built, Guest Additions, snapshot. Your real files are never at risk.

Every distro has its own installer with its own personality, but the VirtualBox part — the part beginners fear — is identical for all of them. Learn this flow once and you can try any Linux distribution this weekend, safely, without touching your real system. The distro cards below plug into these exact steps.

1. Download VirtualBox and the ISO

Install VirtualBox from virtualbox.org (free, Windows/Mac/Linux hosts). Then download your distro's ISO — the install image, usually 1–6 GB — from the distro's official site only. An ISO is a disk in a file: VirtualBox will pretend it is a DVD in a drive.

2. Create the virtual machine

In VirtualBox: New. Give it a name ("Ubuntu test"), set Type to Linux and Version to the closest match for your distro (for example "Ubuntu (64-bit)" or "Debian (64-bit)"). Getting the version roughly right matters — it tunes defaults like the disk controller.

3. Size the RAM and CPU

Rule of thumb: never give the VM more than half your real RAM. 4 GB is a comfortable default for desktop distros (2 GB works for light ones; Kali prefers 4). Give it 2 CPU cores if your machine has 4 or more. The VM only uses this while it runs.

4. Create the virtual disk

Choose "Create a virtual hard disk now", type VDI, and — the important one — Dynamically allocated. Size: 25 GB is a safe default (30–40 for Kali with its toolset). Dynamic allocation means the file starts small and grows only as the VM actually stores data, so "25 GB" is a ceiling, not a chunk carved out of your drive today.

The safety factThat virtual disk is a single ordinary file on your computer (something like Ubuntu.vdi). The Linux inside can format it, encrypt it, destroy it — your real Windows files, photos and documents are not in that file and cannot be touched. This is the entire reason VMs are the right way to learn.

5. Attach the ISO

Select your VM → Settings → Storage → click the empty optical drive → "Choose a disk file" → pick the ISO you downloaded. The VM now believes a Linux DVD is inserted.

6. Boot and install

Start the VM. It boots from the ISO into a live session or installer. The flow is always some version of: language → keyboard → "Install" → time zone → your name and password. When it asks about the disk and offers "Erase disk and install", say yes without fear — the "disk" is your virtual file from step 4, nothing else. This is the moment the VM design earns its keep.

7. Reboot and remove the ISO

When the installer finishes it asks to restart and remove the installation medium. VirtualBox usually ejects the ISO for you; if the VM boots back into the installer, shut it down, remove the ISO in Settings → Storage, and start again — you will boot into your fresh Linux.

8. Install Guest Additions

This is the step that turns a clunky VM into a pleasant one: automatic window resizing, shared clipboard, drag-and-drop. With the VM running: Devices → Insert Guest Additions CD image, then inside Linux open the mounted disc and run the installer (or, on Debian-family systems, install the package):

sudo apt update
sudo apt install -y virtualbox-guest-utils virtualbox-guest-x11

Reboot the VM afterwards. The Sandbox has a simulated run of exactly this post-install terminal session.

9. Take a snapshot

With everything fresh and working: Machine → Take Snapshot, name it "Fresh install". A snapshot is a save point for the whole machine. Every experiment you ever do starts from here — and if one goes wrong, you restore instead of reinstalling. Snapshot first is the single habit that separates calm learners from reinstall veterans.

Set up your first security lab

A legal, breakable playground: Kali in VirtualBox, the network modes explained without the danger, snapshots before experiments, and the first five commands worth typing.

Security skills are learned by breaking things, and breaking things needs a place where it is legal, safe, and reversible. That place is a lab: virtual machines on your own computer, deliberately isolated, snapshotted before every experiment. Here is the beginner build — one afternoon, no extra hardware.

The machine: Kali in VirtualBox

Install Kali Linux using the universal VirtualBox flow in the guide above — or skip the install entirely with Kali's official prebuilt VirtualBox image (import it, log in, change the default password). Kali arrives with the standard security toolkit preinstalled, which is its entire purpose. The moment it boots cleanly, take a snapshot named "Clean Kali". Every experiment starts by restoring to a known-good machine.

Network modes, explained safely

This setting decides who your VM can talk to, and it is the one place beginners can genuinely cause trouble. Three modes matter:

  • NAT (the default) — the VM can reach the internet through your host, but nothing on the internet or your home network can reach in. Safe default for updates and general use. Start here.
  • Host-only — the VM can talk to your host and your other VMs, and nothing else. No internet at all. This is the mode for attack-and-defend practice between your own machines.
  • Bridged — the VM joins your real network like another computer, with its own address, visible to everything else on it. Tools run in this mode can touch real devices. Avoid it until you can explain exactly why you need it.

Rule of the lab: if you are not sure which mode you are in, you are not ready to run the tool. NAT or Host-only, always, while learning.

Your first five commands

whoami
Who the terminal thinks you are. In Kali this answers kali — an ordinary user, despite the legends.kali@kali:~$ whoami
ip a
Your network addresses. Find the VM's own IP (often 10.0.2.15 under NAT) — you cannot practise networking without knowing where you live.kali@kali:~$ ip a
ping
The simplest "is anything there?" test there is. Three pings to a public DNS address prove your NAT networking works.kali@kali:~$ ping -c 3 1.1.1.1
sudo apt update
Refreshes the package lists so installs and upgrades offer current versions. Your first real use of sudo — one command, run as root, on purpose.kali@kali:~$ sudo apt update
nmap --version
Checks the famous scanner is installed and shows its version. Run it on day one just to prove the toolkit is real — scanning comes later, in scope, in the lab.kali@kali:~$ nmap --version

Lab rules

  • Snapshot before every experiment; restore without sentimentality when one goes sideways.
  • NAT or Host-only networking only. Bridged stays off.
  • Scan and test only machines inside this lab, or systems you have written permission to test.
  • Keep a notes file: command, what you expected, what actually happened. That file becomes your real textbook.

Linux terminal: the 15 commands that do 90% of the work

There are thousands of commands. Working in the terminal daily uses a small cast of them, over and over. Learn these fifteen and the terminal stops being a wall of text.

The terminal looks infinite from outside. From inside, a working day is the same handful of commands in rotation: look around, go somewhere, move files, read files, search files, install things. Here is that handful — the fifteen that genuinely do about ninety percent of the work — each with the one example worth memorising.

ls
List what is in the current folder. Add -la to include hidden files and details.$ ls -la
cd / pwd
cd changes folder; pwd prints where you are standing when you get lost. Everyone gets lost.$ cd ~/Downloads  ·  $ pwd
mkdir
Make a folder. The first thing you will do in every project, forever.$ mkdir projects
cp
Copy a file. Add -r for a whole folder.$ cp notes.txt notes-backup.txt
mv
Move a file — and, if the destination is the same folder with a new name, rename it.$ mv draft.txt final.txt
rm
Delete. Permanently — there is no recycle bin here, and rm -rf deletes folders and everything inside them without asking. The danger command: read the line twice before pressing Enter, every time.$ rm old-file.txt
cat
Print a whole file to the screen. Perfect for short files: configs, notes, readmes.$ cat .env.example
less
Read a long file a page at a time, with searching inside (/word) and q to quit.$ less /var/log/syslog
grep
Search inside text. The single most-used debugging command in existence: find every line that mentions a word.$ grep "error" app.log
find
Locate files by name anywhere under a folder. Your lost-file rescue service.$ find ~ -name "*.iso"
chmod
Change who may read, write or run a file. At concept level: owner / group / everyone, each with r-w-x permissions. The +x form makes a script runnable.$ chmod +x setup.sh
sudo
Run one command as root, the system boss. Honest framing: sudo is not a magic prefix for fixing errors — it removes the guardrails for that one command, so the command had better deserve it.$ sudo apt update
apt
The Debian-family software store, in text form: update refreshes the catalogue; install does what it says. (Fedora uses dnf, Arch uses pacman — same idea.)$ sudo apt install nmap
man
The manual. Every command ships its own documentation, offline, written by the people who built it. Try man before any search engine.$ man grep
history
Everything you have run, numbered. Combine with grep to answer "what was that command from Tuesday?"$ history | grep ssh

Fifteen commands, honestly learned — typed by hand, not pasted — will carry you through almost any tutorial, server, or security lab on this site. The other thousands are specialists. These are the residents.

Distro library (58 distros)

Debian

Stable server classic•Intermediate•APT (.deb)

People who value calm over newness. Debian powers half the servers you will ever meet, and changes slowly on purpose.

ISO: netinst ≈ 0.7 GB (downloads the rest) · VM: 2–4 GB RAM, 20 GB disk

Watch out: The installer asks more questions than Ubuntu's, and if you skip selecting a desktop environment you will boot to a bare text login. That is a choice you made, not an error.

  1. Pick Graphical install from the boot menu, then set language, location and keyboard.
  2. It configures the network automatically (the VM's NAT connection just works), then asks for a hostname.
  3. Set a root password, then create your everyday user account and its password — two separate accounts, that is normal here.
  4. Partitioning: choose "Guided — use entire disk", pick the virtual disk, and "All files in one partition".
  5. Software selection: tick a desktop environment (GNOME is the default; Xfce is lighter) plus "standard system utilities" — skip this screen and you get no desktop.
  6. Say yes to installing the GRUB bootloader on the disk, reboot, and remove the ISO.

The netinst image is small because it downloads packages during install, so keep the VM's network connected. Modern Debian images include the firmware real hardware needs, so the old "wifi driver hunt" is mostly history. Debian is also the base Ubuntu, Mint and Kali are built on — learn it once and half this library feels familiar.

Ubuntu

Beginner default•Beginner•APT (.deb) + Snap

Your first distro. The biggest community, the most tutorials, and nearly every guide on the internet quietly assumes it.

ISO ≈ 6 GB · VM: 4 GB RAM, 2 cores, 25 GB disk

Watch out: The first boot can feel slow while it indexes and updates. Some apps ship as Snaps and open a touch slowly the first time — normal, not broken.

  1. Boot the ISO and choose "Install Ubuntu" (or "Try Ubuntu" first to look around — the installer icon is on the desktop).
  2. Language and keyboard layout, then how updates and third-party drivers/codecs should be handled — ticking the third-party box saves errands later.
  3. Installation type: "Erase disk and install Ubuntu" — inside a VM, that disk is the virtual file, not your computer.
  4. Pick your time zone on the map, then create your user: name, computer name, username and password.
  5. Let it copy and finish, click "Restart now", and remove the ISO when it asks.

When something goes wrong, search your exact error plus "Ubuntu" — with this many users, someone has already had your problem and written the answer. In VirtualBox, "Ubuntu (64-bit)" is the version to pick when creating the VM.

Linux Mint

Easiest start from Windows•Beginner•APT (.deb)

Windows refugees. The Cinnamon desktop has the taskbar, start menu and window habits your hands already know.

ISO ≈ 2.8 GB · VM: 4 GB RAM (2 works), 25 GB disk

Watch out: Do not bring Windows habits with you: no .exe installers, no downloading random setup files. Software comes from the built-in Software Manager.

  1. Boot into the live desktop first — Mint always lets you look before you leap. Double-click "Install Linux Mint".
  2. Language, keyboard, then tick the box to install multimedia codecs.
  3. Installation type: "Erase disk and install Linux Mint" (in a VM that is only the virtual disk).
  4. Time zone, then your name, username and password.
  5. Reboot when it finishes and remove the ISO/USB when prompted.

After install, run the Update Manager once and open the Welcome screen's Driver Manager — Mint is deliberately boring after that, which is the compliment it wants. In VirtualBox, version "Ubuntu (64-bit)" is the closest match, since Mint is built on Ubuntu.

Pop!_OS

Polished · gaming-friendly•Beginner•APT (.deb)

Made by the laptop maker System76, for anyone: a clean, keyboard-friendly desktop with the friendliest NVIDIA support in the business — there is a separate download with the NVIDIA driver already in it.

ISO ≈ 2.5–4 GB (NVIDIA image is bigger) · VM: 4 GB RAM, 25 GB disk

Watch out: Two downloads exist: standard and NVIDIA. On real hardware with an NVIDIA graphics card, get the NVIDIA one. In a VM it makes no difference.

  1. Boot the ISO into the live desktop, choose language and keyboard.
  2. Choose "Clean Install" — this erases the selected disk (only the virtual disk, in VirtualBox).
  3. Optionally enable drive encryption on a real laptop; skip it in a learning VM.
  4. It installs, then reboots into a short welcome flow where you create your user account and pick your theme.

Pop!_OS shines on real hardware: hybrid-graphics switching, the optional NVIDIA image, and the Pop!_Shop store. Its window tiling mode is a quiet productivity superpower — try it from the top-right menu once you are settled.

MX Linux

Lightweight · old hardware hero•Beginner•APT (.deb)

The revival specialist: MX takes laptops that Windows has given up on and makes them feel responsive again, with a toolbox of friendly utilities (MX Tools) no other distro matches.

ISO ≈ 2 GB · VM: 2 GB RAM, 20 GB disk

Watch out: MX runs beautifully live from USB, and its installer can preserve your /home folder — read each screen; the defaults are safe, the options are powerful.

  1. Boot the live system (it is fast — that is the point) and click the installer icon on the desktop.
  2. Keyboard first, then the disk step: choose "Auto install using entire disk" for the simple path.
  3. Set the computer name (defaults are fine), then create your user and set the root password.
  4. It installs quickly; reboot and remove the ISO/USB.

First stop after install: MX Package Installer, which adds popular apps (including ones from outside the main repos) in one click, and the main updater in the panel. MX also makes a bootable snapshot of your whole system onto USB — a party trick worth learning later.

Kali Linux

Security toolbox•Intermediate•APT (.deb)

Security learners. Hundreds of testing tools preinstalled and organised — pair it with the lab guide in this section.

ISO ≈ 4 GB, or the ready-made VirtualBox image · VM: 4 GB RAM, 30 GB disk

Watch out: A specialist tool, not a daily driver — do not browse, bank and live in Kali. And know the shortcut: the official prebuilt VirtualBox image skips installing entirely.

  1. From the ISO, choose Graphical install. Language, location, keyboard.
  2. Create your user — modern Kali runs as this ordinary user, not as root (a deliberate, good change).
  3. Partitioning: "Guided — use entire disk", all files in one partition.
  4. Software selection: leave the default toolset ticked for your first install; the "large" set is a big download you can add later.
  5. Install GRUB on the disk, reboot, remove the ISO.

The faster VirtualBox route: Kali publishes a prebuilt VirtualBox image. Download it, import the appliance (File → Import), boot, log in — then immediately change the default password and take your "Clean Kali" snapshot. Everything Kali assumes about networking and safety is in the "Set up your first security lab" guide above.

Parrot OS

Security + privacy daily driver•Intermediate•APT (.deb)

Kali's friendlier rival: the same family of security tools, but packaged as a system you can also live in — plus privacy tooling (Tor routing options, encrypted tools) built in. Security edition for testing work, Home edition for everyday use.

ISO ≈ 4–5 GB · VM: 4 GB RAM, 30 GB disk

Watch out: Pick the right edition: Security for the toolset, Home for a daily system without it. Like Kali, it belongs in a VM for lab work, not as your bank-and-browse machine.

  1. Boot the live desktop and start the Install Parrot installer (Calamares).
  2. Language, keyboard and time zone.
  3. Disk step: "Erase disk" — in a VM, that is only the virtual disk.
  4. Create your user and password, confirm the summary, install, reboot, remove the ISO.

Parrot uses its own repository on top of Debian, kept deliberately conservative about updates. Its AnonSurf tool routes traffic through Tor — know what that does and does not protect before relying on it; the honest explanation is in the "Which distro for which job" article.

Tails

Amnesic · leaves no trace•Intermediate•Debian base (software pre-selected)

The amnesiac: Tails runs entirely from a USB stick, routes everything through Tor, and forgets everything when you shut down. Built for journalists, activists, and anyone using a computer they cannot trust.

USB image ≈ 1.5 GB · Runs from USB · 2 USB sticks recommended for install

Watch out: Tails is not installed like other distros, and that is the point. Anything you want kept needs its encrypted Persistent Storage — and enabling it is a decision, not a default.

  1. On the Welcome Screen, choose your language and keyboard; this is also where you unlock Persistent Storage if you created it.
  2. Connect to Tor when prompted — the connection assistant handles bridges if Tor is blocked on your network.
  3. That is the whole "install": the desktop you reach is the system, running from the stick.

Because Tails resets itself, updates work differently: when a new version exists, Tails tells you at boot and upgrades the stick itself, with a manual-upgrade path (a second stick) when a release is too big for the automatic one.

Raspberry Pi OS

For the Raspberry Pi•Beginner•APT (.deb)

The official system for the Raspberry Pi: a friendly Debian-based desktop tuned for the little ARM boards, with the huge Pi community and its project tutorials behind it.

Image written to microSD · Pi: 2 GB+ RAM recommended · VM (PC edition): 2 GB RAM, 20 GB disk

Watch out: Two different things share this name. The Pi image will not run on a normal PC or in a standard VirtualBox VM — for PCs there is a separate 'Debian with Raspberry Pi Desktop' download. Match the download to the hardware.

  1. Download Raspberry Pi Imager from the official site (Windows, Mac, Linux all fine).
  2. Choose OS → Raspberry Pi OS (pick the desktop edition), choose your microSD card as storage.
  3. Use Imager's settings (gear icon) to pre-set your username, password and wifi — this saves typing later.
  4. Write the card. Everything on it is erased.
  5. Put the card in the Pi, connect screen, keyboard and power, and it boots to the desktop (a short setup wizard finishes account and update checks).

The Imager route replaces the USB-installer dance entirely — there is no ISO-to-disk installer on the Pi itself. Everything after that is Debian: same APT, same commands, same family as Ubuntu and Mint.

elementary OS

Design-first · beautiful•Beginner•APT (.deb) + Flatpak

The design student's distro: a coherent, opinionated, genuinely beautiful desktop (Pantheon) with its own curated app store. If you care how a system feels, start here.

ISO ≈ 3 GB · VM: 4 GB RAM, 25 GB disk

Watch out: The download page suggests a payment — it is pay-what-you-want; entering a custom amount of 0 is an offered option. Also: elementary is minimal by design, and its AppCenter favours apps built for it.

  1. Boot the ISO, pick language and keyboard.
  2. Choose "Erase Disk and Install" for the clean path (in a VM, only the virtual disk is erased), with optional encryption on real hardware.
  3. It installs and reboots into a short setup: create your user account, pick light/dark and accent colour.

Updates and apps arrive through AppCenter; under the hood it is Ubuntu LTS, so the terminal commands and most Ubuntu help pages apply. Its multitasking view and picture-in-picture mode are worth the first tour.

Zorin OS

Feels like Windows or macOS•Beginner•APT (.deb)

Built to receive defectors: Zorin Appearance switches the desktop between Windows-like and macOS-like layouts in one click, and it detects Windows apps you try to run and suggests alternatives.

ISO ≈ 3.5 GB · VM: 4 GB RAM, 25 GB disk

Watch out: There is a paid 'Pro' edition with extra layouts and bundled apps; the free Core edition is the full operating system — the one to install.

  1. Boot the ISO and start the installer (Ubuntu's flow): language, keyboard.
  2. Tick third-party drivers/codecs, then "Erase disk and install Zorin OS" in a VM (or "Install alongside" on a real dual-boot).
  3. Time zone, user account, install, reboot, remove the ISO/USB.
  4. After first login, open Zorin Appearance and pick the layout that matches your muscle memory.

Zorin is Ubuntu-based, so APT and Ubuntu help pages all apply. Its Windows App Support helper (Wine-based) is honest about being a bridge, not a promise — most switchers end up on native apps within a month.

Linux Lite

Light · beginner-friendly•Beginner•APT (.deb)

Aimed squarely at Windows users with modest PCs: Xfce kept deliberately familiar, helpful 'Lite Tweaks' tools for cleaning and fixing, and documentation written for non-experts.

ISO ≈ 2.5 GB · VM: 2 GB RAM, 20 GB disk

Watch out: Lite's friendliness assumes you use its tools — Lite Tweaks, Lite Software and its update notifier — instead of random forum one-liners.

  1. Boot the live desktop, click Install Linux Lite (Ubuntu-style installer): language, keyboard.
  2. Tick third-party software, then "Erase disk and install" for the simple route.
  3. Time zone, user, install, reboot, remove the ISO/USB.
  4. First login: run the offered updates, then look in Menu → Settings for the Lite tools.

Updating regularly is mostly clicking the notifier; the terminal route is the standard Debian-family one below. Lite is Ubuntu LTS underneath, so version upgrades follow Ubuntu's LTS rhythm.

Peppermint OS

Light · web-app focused•Beginner•APT (.deb)

A featherweight Debian base with a clever idea: web apps as first-class desktop apps. Its Kumo tool turns any website into a windowed 'app' — perfect for low-storage machines that live in the browser anyway.

ISO ≈ 2.5 GB · VM: 2 GB RAM, 20 GB disk

Watch out: Peppermint installs lean on purpose; some things you expect preinstalled arrive when you ask for them. The Welcome screen is the tour guide — take it.

  1. Boot the live desktop and start the installer (Calamares): language, keyboard, time zone.
  2. Disk step: "Erase disk" for the simple path (virtual disk only, inside a VM).
  3. Create your user, install, reboot, remove the ISO/USB.

Old Peppermints were Ubuntu-based; current ones are Debian-based — download the current image from the official site and this guide still fits. After install, updates and software are standard APT.

Devuan

Debian without systemd•Advanced•APT (.deb)

Debian, forked at one specific decision: no systemd. Devuan lets you pick your init system (sysvinit, OpenRC, runit) and is the refuge for admins who want Debian's stability with the classic init model.

ISO: installer or live ≈ 1–4 GB by edition · VM: 2 GB RAM, 20 GB disk

Watch out: This distro exists for people with a formed opinion about init systems. If you do not have one yet, plain Debian is the simpler start — Devuan will still be here when you do.

  1. Boot the installer ISO: language, keyboard, network.
  2. Create user and root password (Debian-style), partition with "Guided — use entire disk".
  3. On expert installs you choose the init system; the standard path picks a sane default.
  4. Software selection: tick a desktop if you want one, install GRUB, reboot, remove the ISO.

Package-for-package, Devuan tracks Debian, so Debian documentation mostly applies — the difference is under the floorboards, in how services are started and supervised.

antiX

Featherweight · ancient hardware•Intermediate•APT (.deb)

The floor of the possible: antiX runs a full desktop in a few hundred megabytes of RAM, reviving machines from the Windows XP era. It is also proudly systemd-free and lightning-fast live from USB.

ISO ≈ 1–2 GB by edition · VM: 1 GB RAM, 10 GB disk

Watch out: The 'full' edition is the one to download; 'base' and 'core' are for builders. On truly ancient PCs the 32-bit image still exists — one of the last distros to offer one.

  1. Boot the live system (it starts fast, even from USB) and run the antiX installer from the menu.
  2. Choose the disk and "auto-install" for the simple path, or partition by hand.
  3. Set the computer name, create your user, set passwords, install, reboot, remove the ISO/USB.

antiX shares MX Linux's toolbox DNA, and its control centre covers most tasks without a terminal. It is the honest recommendation when a machine has 2 GB of RAM or less — see the "old laptops" section of the which-distro article.

Deepin

Visually polished desktop•Beginner•APT (.deb)

China's flagship desktop distro, famous for the DDE desktop: translucent panels, graceful animations, and its own suite of polished in-house apps (music, video, file manager) that other distros borrow.

ISO ≈ 4 GB · VM: 4 GB RAM, 30 GB disk

Watch out: Deepin's own app store and mirrors are tuned for its home audience; downloads can be slow elsewhere. Check the privacy settings on first run, as with any system, and set them your way.

  1. Boot the ISO and pick your language in Deepin's own installer.
  2. Choose the disk for a full-disk install (the simple route; in a VM only the virtual disk is affected).
  3. It installs, reboots, and a guided setup walks you through user creation, desktop mode (fashion/efficient) and effects.

Deepin is Debian-based, so APT works as usual, but its own App Store is the intended front door. The Control Center centralises settings the way a phone does — one of the friendliest in Linux.

KDE neon

Newest KDE Plasma, first•Intermediate•PackageKit (pkcon) on Ubuntu LTS base

The KDE project's own showcase: a stable Ubuntu LTS base carrying the very latest KDE Plasma desktop and KDE apps, updated the moment KDE ships them. For Plasma fans, it is the source.

ISO ≈ 2.5 GB · VM: 4 GB RAM, 25 GB disk

Watch out: neon is a showcase, not a general-purpose flagship: the base stays LTS-old while Plasma stays brand-new, and KDE asks you to update with pkcon, not apt upgrade (see first commands).

  1. Boot the live desktop, click Install KDE neon (Calamares): language, keyboard, time zone.
  2. Disk: "Erase disk" for the simple path.
  3. Create your user, install, reboot, remove the ISO/USB.

One honest rule from neon's own FAQ: use pkcon for system updates (it handles the full upgrade correctly), and reboot after big Plasma updates rather than logging back into a half-updated desktop.

Kubuntu

Ubuntu · KDE Plasma edition•Beginner•APT (.deb) + Snap

Ubuntu with KDE Plasma instead of GNOME: the same huge ecosystem, but a desktop that bends to your will — panels, widgets and shortcuts all rearrangeable. The official flavour for people who like to tune.

Arch Linux

Advanced · manual install•Advanced•Pacman

People who want to understand every layer because they assembled every layer. The Arch Wiki is the best Linux documentation on Earth.

ISO ≈ 1 GB · VM: 2–4 GB RAM, 20 GB disk

Watch out: Honest warning: there is no classic point-and-click installer. You partition disks and install packages by hand (the archinstall script softens this a lot). A brilliant teacher, a poor first distro.

  1. Boot the ISO and you land at a root prompt — no desktop, no wizard. Connect the network (automatic in a VM; iwctl for wifi on real hardware).
  2. Partition the disk with fdisk or cfdisk, format the partitions, and mount them under /mnt.
  3. Install the base system: pacstrap -K /mnt base linux linux-firmware, then generate the filesystem table with genfstab.
  4. arch-chroot /mnt into your new system: set time zone, language, hostname, root password, and install a bootloader (GRUB) — then install a desktop if you want one.
  5. Exit, unmount, reboot, remove the ISO: you boot into the system you built.

The middle path: the bundled archinstall script turns all of this into a guided menu and produces a genuine Arch system — a reasonable first Arch install, after which the manual route teaches you what the script did. Either way, the Arch Wiki installation guide is the authority; follow it, not memory, not a video. Do Arch in a VM, with snapshots, after the 15-commands guide feels easy.

  4. Configure the bootloader (ELILO/LILO), network, timezone and root password in the setup flow's final screens.
  5. Reboot, remove the ISO, and create your everyday user with adduser before settling in.

Slackware's stability secret is restraint: vanilla packages, minimal patching, releases when they are ready. Systems installed in the 2000s were upgraded for decades — that is the culture you are joining.

Void Linux

Lean · runit · independent•Advanced•XBPS

A rolling distro built entirely from scratch by its own community: its own package manager (XBPS, fast), the runit init system (tiny, transparent), and a choice of glibc or musl. Feels like Arch's quieter sibling.

ISO ≈ 0.6–1 GB · VM: 2 GB RAM, 15 GB disk

Watch out: Rolling and DIY: services are enabled by linking them yourself (one command, below in spirit — the installer notes cover the base). Also choose deliberately between glibc (maximum compatibility) and musl (maximum lean) images.

  1. Boot the live image, log in (the image prints its credentials: usually anon or root with password voidlinux).
  2. Run sudo void-installer and walk its menus: keyboard, network, source, hostname.
  3. Partition the disk inside the installer, set the filesystem mount points, and let it install the base system.
  4. Set the root password and your user when prompted; install the bootloader.
  5. Reboot, remove the ISO, and log in — then enable the services you want, runit-style (ln -s /etc/sv/<service> /var/service/).

XBPS is genuinely quick, and Void's repositories are rolling but curated for stability. The musl edition is a favourite for containers and minimal systems; desktop users usually want glibc for proprietary software compatibility.

NixOS

Declarative · reproducible•Advanced•Nix

The radical one: your entire system — packages, services, users — is declared in one configuration file, and the OS builds itself from that declaration. Rollback to yesterday's system is a boot-menu entry. Developers and reproducibility obsessives swear by it.

ISO ≈ 2.5 GB · VM: 4 GB RAM, 30 GB disk

Watch out: Throw away your package-manager reflexes: you do not 'install' apps onto NixOS the normal way — you declare them. The first week bends your brain; the payoff is a machine you can rebuild from one file.

  1. Boot the ISO and the graphical installer starts: language, keyboard, time zone.
  2. Choose your desktop (GNOME, Plasma, or none), then the disk step: "Erase disk" for the simple path.
  3. Create your user, install, reboot, remove the ISO.
  4. Your system now lives in /etc/nixos/configuration.nix — edit it, and run the rebuild command below to change anything.

Try software without committing: nix-shell -p <package> gives you a temporary shell with it, gone when you exit. Every rebuild keeps the previous generations in the boot menu — that is the rollback that makes NixOS users so calm.

Alpine Linux

Tiny · container king•Intermediate•apk

The 5-megabyte miracle behind half the world's Docker images: musl libc, BusyBox utilities, and a security-first minimalism. As a desktop it is a hobbyist's choice; for containers and lean servers it is an industry default.

ISO ≈ 0.2–0.9 GB by edition · VM: 1 GB RAM, 8 GB disk

Watch out: Alpine uses musl, not glibc: some prebuilt commercial software will not run on it. For a server/container that rarely matters; for a desktop it decides everything. The 'extended' ISO is the one with useful extras offline.

  1. Boot the ISO and log in as root (no password on the live image).
  2. Run setup-alpine and answer its questions: keyboard, hostname, network interface (automatic in a VM), time zone.
  3. Create your user when offered, pick the package mirror it suggests, then choose the disk and the "sys" mode (a normal disk install).
  4. It installs in about a minute. Reboot, remove the ISO, log in.
  5. Want a desktop? Add it after: Alpine's wiki documents setup-desktop.

apk is quick and its package files are refreshingly readable. If you meet Alpine inside Docker (likely), everything here applies — the same commands run your containers.

Solus

Independent · curated rolling•Beginner•eopkg

A rolling distro built from scratch for home desktops, home of the Budgie desktop: curated (software is picked and tested rather than merely mirrored), stateless in design, and aimed at people who just want a handsome system that keeps itself current.

ISO ≈ 2.5–3.5 GB by edition · VM: 4 GB RAM, 25 GB disk

Watch out: Curated means smaller: if your favourite obscure app is missing, the Software Center takes requests — and Flatpak covers the gaps.

  1. Boot the live desktop of your chosen edition and click the installer.
  2. Language, keyboard, time zone.
  3. Disk: automatic partitioning of the whole disk is the simple path ("Erase disk" equivalent).
  4. Create your user, install, reboot, remove the ISO/USB.

Solus is neither Debian, Arch nor Red Hat family — its own thing, with its own package tools (below). After install, the Software Center handles most needs graphically; updates arrive continuously with the rolling model, tested weekly by the project.

Mageia

Community classic · friendly•Beginner•urpmi / DNF (.rpm)

The community fork of the beloved Mandriva, carrying its traditions forward: a famously friendly installer and the Mageia Control Center, one of the best graphical system-administration panels Linux has ever had.

ISO ≈ 4 GB · VM: 4 GB RAM, 25 GB disk

Watch out: Mageia releases on its own measured schedule and values stability; if you want frantic newness, look at the rolling shelves of this library instead.

  1. Boot the ISO (or a live edition) and start the installer — it is the classic, well-loved DrakX flow.
  2. Language, keyboard, then partitioning: "Use entire disk" for the simple path.
  3. Choose your desktop when the package groups are offered (Plasma is the flagship).
  4. Create your user and root password, let it install, reboot — a summary screen lets you tune network and services before first boot.

After install, the Mageia Control Center is your cockpit: software, hardware, network sharing, firewalls — a control-panel completeness Windows users find oddly comforting. Package management is urpmi by tradition, with DNF also supported.

PCLinuxOS

Easy · rolling · community•Beginner•APT-RPM + Synaptic

A long-running community distro with one goal: easy. It rolls (continuously updated), uses the Synaptic graphical package manager over an RPM base, and asks almost nothing of the user beyond enjoying the ride.

ISO ≈ 2–3 GB by edition · VM: 4 GB RAM, 25 GB disk

Watch out: Its rule is famous and strict: update fully, always — partial upgrades are unsupported. The Synaptic 'Reload → Mark All Upgrades → Apply' ritual is the way; the commands below do the same.

  1. Boot the live desktop — PCLinuxOS installs from the running system. Double-click Install PCLinuxOS.
  2. Pick the disk and the automatic layout for the simple path.
  3. Set the root password and create your user in the install flow.
  4. Install, reboot, remove the ISO/USB, log in.

PCLOS preserves a classic virtue: it ships working multimedia and broad hardware support out of the box. Its magazine (yes, a community magazine) and forums are part of the charm — a distro that still feels handmade.

Clear Linux

Discontinued — July 2025•Intermediate•swupd (bundles)

Intel's own distribution, optimised relentlessly for Intel hardware and cloud workloads: fast defaults, stateless design, software in 'bundles'. Historical entry: Intel discontinued Clear Linux in July 2025 — it receives no updates and should not be a new install.

ISO ≈ 3 GB · VM: 4 GB RAM, 25 GB disk · DISCONTINUED July 2025

Watch out: Intel ended Clear Linux in July 2025 and archived the project: no security updates will ever arrive. Do not install it as a new system — this guide stays for existing users and the historical record. Also know its model before mourning it: bundles and statelessness, with system directories reset to factory state.

  1. Boot the live image and launch the installer (a text-guided installer on the server image; graphical on the desktop image).
  2. Language/keyboard, network check, then the target disk — the whole disk is the simple path (the installer asks for an explicit confirmation).
  3. Create your user (it can be added to the admin group in the same flow), install, reboot, remove the ISO.

If anything misbehaves after your experiments, Clear's stateless design is the recovery: the OS can verify and repair its own files with swupd repair. Performance claims are its reputation — benchmarks on Intel hardware have kept it famous.

Qubes OS

Security by isolation•Advanced•Xen + per-template managers

Not really a distro — a security architecture: your life is split into isolated virtual machines ('qubes') — work, personal, banking, disposable — so one compromised app cannot reach the rest. Endorsed by security professionals who accept its costs.

ISO ≈ 6 GB · Needs: 64-bit CPU with VT-x + VT-d/IOMMU, 16 GB RAM recommended · Bare metal only

Watch out: Check the hardware requirements and the Hardware Compatibility List on the official site before committing — Qubes needs virtualisation extensions with an IOMMU, and it will refuse or limp without them. It is also a lot of computer to run: 16 GB of RAM is the realistic floor.

  1. Boot the USB installer: language, then the Anaconda-style hub.
  2. Installation Destination: choose the disk and set disk encryption (LUKS) — on Qubes this is not optional thinking.
  3. Create your user; the installer then offers the default qubes layout (sys-net, sys-firewall, personal, work, vault and disposables) — accept the defaults on a first install.
  4. Reboot, enter your disk password, log in, and complete the first-boot configuration it offers.

Daily life is colour-coded windows from different qubes sharing one screen, with networking forced through a dedicated firewall VM. Updating happens centrally: Qubes' updater refreshes dom0 and the templates (Fedora templates use DNF, Debian templates APT) so your AppVMs inherit the fixes.

Armbian

Debian/Ubuntu for boards•Intermediate•APT (.deb)

The standard system for single-board computers beyond the Raspberry Pi — Orange Pi, Banana Pi, and dozens more: Debian or Ubuntu userlands with kernels tuned per board, shipped as ready images.

Image written to microSD/eMMC · Board-dependent · No x86 ISO

Watch out: Download the image for your exact board model — Armbian images are per-board and one board's image will not boot another. 'Supported' vs 'community' boards differ in how much testing they get; the download page says which.

  1. Download the image for your exact board from the official site, and write it to a microSD card with Balena Etcher (the card is erased).
  2. Insert the card, connect network and power, and give it a few minutes for the first boot (it resizes itself and generates keys).
  3. Log in as root with the default password 1234 over SSH or console — you are immediately forced to change it and create your everyday user.
  4. Run armbian-config for the guided setup: wifi, timezone, hardware toggles, and installing to eMMC/NVMe if your board has it.

After first boot it is the Debian family you know: APT commands below, plus armbian-config's extras. Many home servers, print servers and dashboards quietly run exactly this.

SteamOS

Valve's gaming OS•Beginner•Image-based (Flatpak for apps)

The system of the Steam Deck: a console-simple gaming mode on top of an immutable Arch-based base with a full KDE desktop hiding one menu away. Millions now daily-drive Linux because of it — most without noticing.

Recovery image for Steam Deck · Written to USB for Deck recovery

Watch out: SteamOS 3 is distributed for the Steam Deck, not as a general PC installer. The honest routes to a Deck-like PC are Bazzite (opposite page of this library) or a normal distro plus Steam — not a hacked SteamOS image.

  1. This is the Steam Deck recovery flow: download the recovery image from Steam's official support page.
  2. Write it to a USB stick (16 GB+) with Balena Etcher or Rufus — the stick is erased.
  3. Power the Deck off, hold Volume Down and press Power, and pick the USB in the boot manager.
  4. In the recovery desktop, choose "Reimage Steam Deck" for a full factory reinstall (this erases the Deck's storage), or the repair options for gentler fixes.
  5. The Deck reboots into the standard SteamOS setup: wifi, language, Steam sign-in.

SteamOS updates arrive as system images through Steam itself (Steam button → Settings → System). Desktop-mode software comes from the Discover store as Flatpaks — the base system stays read-only, which is why Decks are so hard to break.

Endless OS

Simple, offline-friendly, for families•Beginner•OSTree + Flatpak

A simplified, family- and education-friendly system built for schools, labs and low- or no-connectivity settings, with a customised GNOME desktop, a read-only system image and a large offline app and content catalogue. Debian-based in origin, but in daily use that barely matters.

Image: Basic or Full from endlessos.com · VM: 2 vCPUs, 4 GB RAM, 32 GB disk (Full images are large)

Watch out: Do not use apt to install software — the system image is read-only and apt is present but unusable for installs; apps come from the App Center (Flatpak) only.

  1. Download the Basic or Full image, write it to USB, and boot from it.
  2. Follow the on-screen installer; a full install wipes the chosen drive — back up first. The Basic image needs internet for apps, while Full images carry much more offline content.
  3. Create your user, finish setup, reboot, remove the USB.

System updates arrive as whole OSTree images with rollback if one fails, and apps update through the App Center.

Guix System

Declarative, reproducible GNU system•Advanced•Guix

The GNU project's advanced, declarative operating system for fully reproducible, transactional systems — every system configuration is written in Guile Scheme and every generation can be rolled back. Best for developers, free-software enthusiasts and anyone who wants to version-control their whole OS.

ISO: installer from guix.gnu.org · VM: 2 vCPUs, 2 GB RAM, 20 GB disk

Watch out: Free-software-only kernel and firmware policy: Wi-Fi and graphics hardware needing proprietary firmware may not work out of the box. Scheme-based configuration is a real learning curve.

  1. Boot the installer ISO and follow the guided installer: language, keyboard, partitioning, user, desktop choice.
  2. Partitioning/formatting during install destroys data on the chosen disk — back up first and double-check the target disk.
  3. Finish the install, reboot, remove the USB.

Guix manages system and packages declaratively: edit /etc/config.scm and reconfigure to change the system, and roll back to any previous generation if a change misbehaves.
